## Workflow / checks
- Push directly to `main`; no branches/PRs. No model names in commits/files. One finding per commit.
- Before push: `npm run lint`, `npm run typecheck`, `npx vitest run`, `npm run build`, `npm run e2e` (anything the smoke suite covers). CI = root `.github/workflows/ci.yml` (jobs `lobby-checks`, `lobby-e2e`, `worker`, deploy); green push redeploys `/lobby/` (signage) and `/lobby/countdown` (projector). Visual baselines (`e2e/__screenshots__`): regenerate ONLY via root workflow `lobby-update-snapshots.yml` (dispatch by hand), never from a sandbox.
- Worker tests: `npx vitest run --config worker/vitest.config.js` in ci `worker` job (root vitest excludes `worker/**`; root lint covers it). Desktop tests: `npx vitest run --config desktop/vitest.config.js` in `desktop-release.yml` only (root vitest excludes `desktop/**`; root `eslint .` lints `desktop/`).
- Stack: React 19 + Vite plain JS (the `M` wrapper takes `ref` as a plain prop), framer-motion, canvas-confetti, Vite `base: './'`, two HTML entries (`index.html`, `countdown.html`), Jelly UI vendored `public/vendor/jelly-ui.js` (provenance `public/vendor/README.md`), hand-written service worker `src/sw.js` (per-build cache version via `serviceWorker()` plugin in `vite.config.js`; JSON/HTML network-first falling back to cache after 8s; `/api` never touched; self-update probes network-ONLY).
- Tailwind 4 is imported ONLY by `src/presentation/index.css` (`@source` pinned to that subtree): signage CSS graph must never see Tailwind.
- No `@types/react`/`@types/react-dom`: `tsc` must never infer them from JS (flaky TS2305). `jsconfig.json` `paths` maps bare `react`/`react-dom` to `types/react.d.ts`/`types/react-dom.d.ts`; importing anything else from bare `react`/`react-dom` in a checked file means adding its declaration there first. Vite ignores jsconfig.
- Constants: `src/lib/constants.js` (signage); operator-tunable ones mirrored as validated `config.js` keys.
- Where screens get data (since 2026-10-03): ONLY the sync Worker live channel `/api/v1/live` (`worker/`), signed in with the church passphrase; not signed in = listens to nothing (status `off`). Pusher is gone from the whole repo (no `pusher-js`, no `?key=`/`?cluster=`/`VITE_PUSHER_*`; saved overrides/old OBS links with them are ignored). Old wire-design text saying "Pusher channel" = the live channel (same events, allowlist sanitizers, sealed envelopes, anti-downgrade). Owner deletes `PUSHER_*` secrets/app by hand.

## Privacy invariant — DO NOT relax
- ONE strict allowlist sanitizer per event type: `src/lib/eventSanitizers.js`, bound per event in `src/hooks/useSocket.js`. Events: `checkin`,`recap`,`checkout`,`tally`,`birthdays`,`ops`,`canary`,`tonight`,`points`,`schedule`,`notice`,`slides`,`settings`. Payload reduced to allowlisted fields before anything else sees it: FIRST NAMES ONLY; never allergy, contact, last names, birth years, photos. Shapes pinned by `src/lib/__fixtures__/contract-vectors.json` (byte-identical mirror of printer's canonical; printer first) + `src/lib/eventSanitizers.test.js`. Preserve on any change to socket layer, sanitizers or banner components.
- String clean-up (`cleanString`, `plainText`) = `shared/text.js`, shared with print server (generated copy `printer/print-server/textClean.js`); limits stay with callers; `shared/text.test.js`. `schedule` sanitizer `sanitizeScheduleEvent`; `src/lib/schedule.js` `sanitizeSchedule` = shared schedule.json parser.
- Name-bearing events ENCRYPTED: `checkin`,`recap`,`birthdays`,`checkout` + `slides` (operator deck, contract v5; chunked, ordered strictly by `publishedAt`, cache `awanaSyncedSlides.v1`, publish token in own storage) + `settings` (contract v6, one frame, allowlisted keys): AES-256-GCM, `src/lib/envelope.js` (publisher `printer/print-server/events.js`, pinned by `envelope-vectors.json`). Rules:
  - Decrypt sits IN FRONT of `dispatchEvent`; a sealed frame is authenticated, not trusted, still passes its sanitizer.
  - Anti-downgrade: once a screen holds a key, a plaintext payload on those events is dropped.
  - Key in its OWN localStorage entry (`src/lib/displayKey.js`); NEVER add to `VALIDATORS` in `src/hooks/useConfig.js` (backs `?config=` and Settings export). `displayKey.test.js` guards.
  - Decrypts serialized through one promise chain per event (out-of-order greetings otherwise).
  - Mission control (settings page only, `src/lib/missionControl.js`, `App.jsx` `mission` reducer) is the ONE other place a first name is held: first name + club + time + id of the last 5 check-ins from the same sanitized (decrypted) frames, in React state only (never storage/network), cleared on sign-out and after 30 min hidden; the TV preview uses `demoNames.js` samples, never these. `useSocket.js` stays the only socket.
  - Display login = sync service sign-in (`src/hooks/useDisplayLogin.js` wraps `useSync`); `src/lib/displayLogin.js` is only logout (clears display key, publish token, fleet-config URL, old `awanaLoginKey.v1`). `useSocket.js` is the ONLY file opening the live channel (`privacyGuard.test.js`: also nothing imports pusher-js).
  - Other events stay plaintext on purpose (lets a screen tell "pipe down" from "cannot read names" from "quiet night"). See `SECURITY.md`.
- `checkout` (who is still here) rendering rules ARE the privacy design: pure `decideBoard()` in `src/lib/checkoutBoard.js`.
  - Comes on by itself 7:30 pm (`PICKUP_START`, `inPickupHours`, `pickupNow`) to midnight every night; no on/off mode/window (owner 2026-10-08); printer publishes only on club nights; clubs chosen under Printing → Pickup list. Before 7:30 a list shows nothing.
  - Below `checkoutBoardNamesAbove` children it stops naming anyone (anonymising). Missing payload renders NOTHING (never an empty board). Not a headcount: strings say "not checked out yet", never "still in the building".
  - Emptied list: "Everyone has been checked out" for `EMPTY_HOLD_MS` (1 min, from `emptySince` stamped in App), then away for the night.
  - "<First name> has checked out" (`src/lib/checkoutLeaves.js`, `useCheckoutBanners`, `CheckoutBanner.jsx`; owner 2026-10-08): departure = multiset difference (first name + club) between two successive FRESH lists seen in a row, in pickup time; never on first list after load/reconnect (any socket status change forgets baseline; Worker replays last list), never from/to a stale list. Name only while NEW list still in names state, else "A child has checked out" (no name/club/colour). One at a time `LEAVE_BANNER_MS` 3s in the foot in the list's place (`lobbyRoom` `banner`); beyond `LEAVE_QUEUE_CAP` 6 collapse into "and N more have checked out"; check-in moment outranks; queue empties outside pickup time; never on OBS feed; all `M.*`. Tests: `src/lib/checkoutLeaves.test.js`, `useCheckoutBanners.test.jsx`, `CheckoutBanner.test.jsx`, `App.overlays.test.jsx`, `e2e/pickup-board.spec.js`.
  - Corner counts down only what the board says (`stillHereCount`, `cornerStillHere`, default on): from 7:30 while board NAMES children, tally slot reads PICKUP + "not checked out yet" (`STILL_HERE_NOTE`, shown even if correction note off). Never while anonymous (small exact number singles children out), never from stale/empty/off board.
  - Foot: one run, club by club (`fitFoot` in `src/lib/overlayFit.js`, youngest first by `getAllClubs()`): plate (white mark, "N waiting"), name chips alphabetical, "+N more" where smallest readable chips cannot hold them.
  - Demo (Settings → What screens show → Pickup board): `demoCheckout`, `SAMPLE_BOARD_NAMES` (obviously made-up); "Show a demo on this TV" `BOARD_DEMO_MS` 20s, this screen only, demo badge + "Demo · sample names"; `decideBoard` `demo` bypasses clock, never the naming rule, never real data; never says "has checked out".

## Zero-animation / `?lowPower=1` (the M rule)
- Journey embeds this app on a Pi Zero with `?lowPower=1` (`src/lib/urlFlags.js`): forces `confettiLevel:'off'` and `reduceMotion:true` for that URL only, beats saved Settings. `src/config.js` defaults stay `'full'`/`false` for everyone: NEVER change defaults to suit one weak embed.
- `reduceMotion:true` = ZERO animation. Framer-motion: EVERY signage component (not `src/presentation/`) imports `M` from `src/lib/motion.jsx`, never `motion` from `framer-motion` (M reads `ZeroAnimationContext` from `App.jsx`, forces `transition={{type:false}}` regardless of caller transition, incl. nested transitions in `exit`/`animate`/variants via `stripTransition`/`stripVariants`; `MotionConfig reducedMotion="always"` also set but only gates positional values). `AnimatePresence`/`MotionConfig` still come from `framer-motion`. `src/lib/sourceScans.test.js` fails any signage file importing an animating export instead of `M`.
- Plain CSS: `App.jsx` toggles `zero-animation-mode` on `<html>`; one blanket rule in `app.css` `.zero-animation-mode, … *, *::before, *::after { animation: none !important; transition: none !important }`. Never list selectors one by one; pseudo-elements must stay named (`*` skips them). `sourceScans.test.js` pins it and fails any pseudo-element animation it would not reach.
- Every animated piece's LAST keyframe is its finished resting state (what `?lowPower=1` freezes on); anything transient ends invisible/off-frame; ambient `repeat: Infinity` loops end on rest.
- Testing motion: vitest fake timers cannot drive framer-motion; Playwright `page.clock` does not drive its opacity (browser timeline): sample moving frames in real time (CDP screencast); paused-clock screenshots only meaningful under `?lowPower=1` (what `e2e/signage.visual.spec.js` uses: paused clock, reseeded Math.random per click, fixture calendar). Structure/copy in jsdom.
- Beats are keyframe lists (`landsAt`/`keyframes`/`holdThenLand`/`holdThenLeave`/`vanishAtSwap`), NEVER `initial` plus long `delay` (a delayed opacity paints its target early).
