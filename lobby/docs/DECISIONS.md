# lobby/ decisions and history
Terse, dated. Rules live in `../CLAUDE.md`; this is the why. Tests cited pin the behavior.

## Motion / zero animation
- `M` replaced `motion` because `MotionConfig reducedMotion="always"` only gates transform/positional values (framer-motion `positionalKeys`), never opacity (verified in its source); nested transitions (`exit`, `animate` target, variants) beat the element prop, so every Pi exit with its own timing still animated until `stripTransition`/`stripVariants`. Blanket CSS rule chosen over selector lists so future animations are covered; pseudo-elements named because `*` skips them and neither property inherits (kit checkbox `::before` pop still played under `?lowPower=1`).
- Verified live: an animated element sampled every 250ms oscillates standalone, flat under `?lowPower=1`; CSS keyframe computed `animation-name` real standalone, `none` under it.
- Beats as keyframes, not `initial` + long `delay`: measured on the real build, framer-motion runs accelerated values (opacity) on the browser timeline and the rest on its JS frameloop, so a long delay can paint the ANIMATE value seconds early. Chrome returns by OPACITY at the swap because OS reduced motion makes every transform instant, delay included.
- Mistake not to repeat: changing `confettiLevel`/`reduceMotion` defaults to suit the Pi embed (the reason `?lowPower=1` exists). Initial pass suppressed only transforms; tightened to true zero.
