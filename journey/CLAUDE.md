# journey/ (Journey kiosk, PC) — agent rules
Machine-oriented index. Rationale/history/dated owner decisions: `docs/DECISIONS.md`. Root rules: `../CLAUDE.md`.

## Purpose
Journey room kiosk at https://awana.kvbchurch.org/journey/ (only correct address; never /public/index.html, never github.io): a Windows PC running the KVBC Awana app (`printer/electron-app/`, Display role, screen "Journey kiosk"), since 2026-10-12 (the Pi Zero is gone: `docs/DECISIONS.md`). Check-in Display (lobby iframe `#checkin-view`) by day; 18:30-19:15 daily the Journey: Advocates lesson (`#journey-view`); club nights 19:00-19:30 Trek's "Small Group Time" card (`#trek-view`). Same URL also opens on Mac/phone and behaves the same everywhere (no device profile).

## Workflow / checks
- Push directly to `main`; no branches/PRs. No model names in commits/files. One finding per commit.
- `public/src/schedule.js` is BUILD OUTPUT. Edit `src/schedule/NN-*.js` (byte concat in filename order, no wrapper/rename/minify; new section = new numbered file; cuts only between top-level statements). Then `npm run build`, `npm test`, `node --check public/src/schedule.js`; commit src + output. `test/schedule-build.test.mjs` + CI fail if stale. Tests/stamp/`site/build.mjs`/lobby `screenSpecs.test.js` read the committed output.
- `npm test` = `node --test` over `test/` (pretest runs `npm run assets`). Chromium tests use `playwright-core`, binary `PLAYWRIGHT_CHROMIUM` else `/opt/pw-browsers/chromium`; skip (and say so) without it.
- CI = root `.github/workflows/ci.yml`; green push redeploys the site. Folder `.github/` is gone/dormant.
- Plain static HTML/CSS/JS: NO framework, NO bundler (only the schedule concat). Only `public/` is deployed (under `/journey/`). `jsdom` + `ffmpeg` are Action-only tool deps. `node_modules/` ignored.
- Debug live: check `<meta name="journey-build">` before suspecting code; hard-refresh Ctrl+Shift+R. Check the URL the kiosk is actually on before blaming the server: self-recovery is not proof of correct config.

## Test traps
- `test/kiosk-dom.mjs` boots real `public/index.html`+`schedule.js` in jsdom (kiosk PC UA `KIOSK_PC` by default, the app's Electron UA, set on `navigator.userAgent` by the harness since jsdom 29 ignores its `userAgent` option, `DESKTOP` = Mac; 4th arg = setup run before schedule.js, 5th = page URL; media/object URLs/Cache API stubbed, `caches` undefined on purpose). jsdom has no `matchMedia`, so a plain boot HAS motion; tests that want instant swaps stub `matchMedia` for reduced motion (`lesson-intro`, `trek`, `motion`). schedule.js is a classic script: top-level `function` reachable on `window`, `let`/`const` state is not.
- jsdom cannot see layout: `control-bar-layout`, `corner-buttons`, `splash-fit`, `big-screen-layout` use real Chromium (answers requests from `public/`, no server, schedule.js not run).
- Test TRIGGERS (ended, stall watchdog, →, fatal error), not just `startTeachingSlides()`.
- Committed `index.html` keeps `content="dev"` and plain asset paths (pinned); `version.json` gitignored.
- A test stamps the real page and fails if any local `src`/`href` lacks `?v=`: add new page assets to `STAMPED_ASSETS` (the phone remote's to `REMOTE_STAMPED_ASSETS`; same test for `public/remote/index.html`).

## Invariants: build/update
- Build id = hash of `journey/public` files (NOT monorepo commit; commit-hash would reload kiosks on every push). `scripts/stamp-build.mjs` (run by `site/build.mjs` on the published copy) writes `public/version.json {build,builtAt}`, `<meta name="journey-build">`, `?v=<id>` on every `STAMPED_ASSETS` path (`src/schedule.js`, `src/style.css`, `src/sync.js`, `brand/tokens.css`, `brand/fonts.css`, `brand/logos/journey-white.svg`, every copy), and `?v=<first 12 hex sha256 of font>` on each font URL in deployed `brand/fonts.css` AND on each `<link rel="preload">` font in `index.html` (same URL as the sheet's, else a second download; `stampFontPreloads()`). Idempotent; THROWS if meta missing, fonts.css missing/empty or names a font not deployed, or index.html preloads a font the sheet does not name or the deploy lacks (fail deploy loudly).
- `?v=` is load-bearing (Chromium reuses fresh subresources across reload).
- Poll: every 3 min + `online` (rate-limit 1/min), `version.json?b=<now>` `cache:'no-store'` via `fetchWithTimeout` 5s vs meta; non-200 = no news (inert).
- Never reload onto old page: fetch `index.html?b=<now>` no-store first, must carry the new build id, else retry next tick.
- Never reload while watched: `safeToReload()` needs no video, no teaching slideshow, no `previewMode`, no reader overlay, Settings closed, no caption prompt, no focused text field, not splash awaiting Begin. A running lesson download does NOT block it (resumes after the reload). Busy => recheck 15s, NO forced deadline. Reload = `location.reload()` via stubbable `reloadPage()`. Nothing persisted. Embedded lobby reloads itself; never reach into the iframe.
- Only a Journey change reloads kiosks (hash of own files).
