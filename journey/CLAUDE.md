# journey/ (Journey kiosk) — agent rules
Machine-oriented index. Rationale/history/dated owner decisions: `docs/DECISIONS.md`. Root rules: `../CLAUDE.md`.

## Purpose
Raspberry Pi Zero (2017, ARMv6, 512MB) Chromium kiosk at https://awana.kvbchurch.org/journey/ (only correct address; never /public/index.html, never github.io). Check-in Display (lobby iframe `#checkin-view`) by day; 18:30-19:15 daily the Journey: Advocates lesson (`#journey-view`); club nights 19:00-19:30 Trek's "Small Group Time" card (`#trek-view`). Same URL also opens on Mac/phone.

## Workflow / checks
- Push directly to `main`; no branches/PRs. No model names in commits/files. One finding per commit.
- `public/src/schedule.js` is BUILD OUTPUT. Edit `src/schedule/NN-*.js` (byte concat in filename order, no wrapper/rename/minify; new section = new numbered file; cuts only between top-level statements). Then `npm run build`, `npm test`, `node --check public/src/schedule.js`; commit src + output. `test/schedule-build.test.mjs` + CI fail if stale. Tests/stamp/`site/build.mjs`/lobby `screenSpecs.test.js` read the committed output.
- `npm test` = `node --test` over `test/` (pretest runs `npm run assets`). Chromium tests use `playwright-core`, binary `PLAYWRIGHT_CHROMIUM` else `/opt/pw-browsers/chromium`; skip (and say so) without it.
- CI = root `.github/workflows/ci.yml`; green push redeploys the site. Folder `.github/` is gone/dormant.
- Plain static HTML/CSS/JS: NO framework, NO bundler (only the schedule concat). Only `public/` is deployed (under `/journey/`). `jsdom` + `ffmpeg` are Action-only tool deps. `node_modules/` ignored.
- Debug live: check `<meta name="journey-build">` before suspecting code; hard-refresh Ctrl+Shift+R. Check the URL Chromium is on (`ps -eo args | grep -i '[c]hromi'`, service `JOURNEY_URL`) before blaming the server: self-recovery is not proof of correct config.

## Test traps
- `test/kiosk-dom.mjs` boots real `public/index.html`+`schedule.js` in jsdom (Pi UA, 1 core => profile low; pass exported `DESKTOP` as 3rd arg for Mac; 5th arg = page URL; media/object URLs/Cache API stubbed, `caches` undefined on purpose). schedule.js is a classic script: top-level `function` reachable on `window`, `let`/`const` state is not.
- jsdom cannot see layout: `control-bar-layout`, `corner-buttons`, `splash-fit` use real Chromium (answers requests from `public/`, no server, schedule.js not run).
- Test TRIGGERS (ended, stall watchdog, →, fatal error), not just `startTeachingSlides()`.
- Committed `index.html` keeps `content="dev"` and plain asset paths (pinned); `version.json` gitignored.
- A test stamps the real page and fails if any local `src`/`href` lacks `?v=`: add new page assets to `STAMPED_ASSETS`.

## Invariants: build/update
- Build id = hash of `journey/public` files (NOT monorepo commit; commit-hash would reload kiosks on every push). `scripts/stamp-build.mjs` (run by `site/build.mjs` on the published copy) writes `public/version.json {build,builtAt}`, `<meta name="journey-build">`, `?v=<id>` on every `STAMPED_ASSETS` path (`src/schedule.js`, `src/style.css`, `src/sync.js`, `brand/tokens.css`, `brand/fonts.css`, `brand/logos/journey-white.svg`, every copy), and `?v=<first 12 hex sha256 of font>` on each font URL in deployed `brand/fonts.css`. Idempotent; THROWS if meta missing, fonts.css missing/empty or names a font not deployed (fail deploy loudly).
- `?v=` is load-bearing (Chromium reuses fresh subresources across reload).
- Poll: every 3 min + `online` (rate-limit 1/min), `version.json?b=<now>` `cache:'no-store'` via `fetchWithTimeout` 5s vs meta; non-200 = no news (inert).
- Never reload onto old page: fetch `index.html?b=<now>` no-store first, must carry the new build id, else retry next tick.
- Never reload while watched: `safeToReload()` needs no video, no teaching slideshow, no `previewMode`, no reader overlay, Settings closed, no caption prompt, no focused text field, not splash awaiting Begin. Busy => recheck 15s, NO forced deadline. Reload = `location.reload()` via stubbable `reloadPage()`. Nothing persisted. Embedded lobby reloads itself; never reach into the iframe.
- Only a Journey change reloads kiosks (hash of own files).

## Invariants: Pi performance / UI
- No click/keypress may await the network before something visible changes: acknowledge first, network later. Indirect waits go through `fetchWithTimeout()`. `requestPlayback()` reveals Journey layer + loading overlay synchronously, probes after; settings panel opens instantly with "Loading lesson list…" -> visible error. Every control has instant `:active` (`transition: none`).
- Loading overlay `#journey-loading` shows on play request, `waiting`; hides on `playing` and every teardown/error path; after ~12s note says internet may be down, points at ⇄ (never waits on network).
- Paint budget (test-pinned, low profile = everything outside the motion block; the Trek card is inside it too): only `@keyframes` = `journey-splash-pulse` (opacity, compositor); no `filter`/`backdrop-filter`/gradients; every `box-shadow`/`text-shadow` zero blur, sole exception `#slide-template` soft text shadow (copies Awana deck).
- Motion (owner 2026-10-12; full profile only, `src/schedule/24-motion.js` + the ONE `@media (prefers-reduced-motion: no-preference)` block at the end of `style.css`): `html.motion-full` set only when `effectiveProfile()==='full'`, not configure mode, no OS reduced motion (follows quality buttons/storage/OS live); every rule in the block starts `html.motion-full`, keyframes `jm-*` move only transform/opacity/clip-path, no transitions, from-side keyframes + `backwards` fill (rest = own style). Low = no class/observer/element/inline style (`test/motion.test.mjs`, brand-kit fence). Entrances only (closing instant): splash, Trek card, placeholder, caption prompt, settings card/rows/menus, Read Prep, handout. Two DOM-watched pieces (never called by the code that changes the view, never awaited): view-flip stinger (journeyView `hidden` flips; click-through overlay ~1s, never at startup or over a playing video, `playing` removes it; splash delays `--jm-lead`) and slide change (counter text: colour band + WAAPI layer animations: background wipe/push, template heading split into `.jm-word` spans (same text/order) slams word by word, bullets cascade; a new press cancels and restarts). NO motion on control bar, captions, loading overlay (over video). Deck pin unchanged; only extra deck rule `html.motion-full .jm-word {display:inline-block}` (pinned).
- Cursor auto-hides after 5s idle (`cursor-hidden` on `<html>`), reappears on mousemove; never `cursor:none` unconditionally. Control bar fades with it (touch counts as activity), pinned visible when paused (`.force-visible`).
- Settings panel is a 10-foot UI (~1.5rem rows, ~1100px card).
- Wake Lock on load, re-acquire on `visibilitychange`; OS blanking off (`PI_SETUP.md`) is the fallback.
- Splash/loading overlays viewport-responsive (`clamp()` + rem floor); Space/→ hint hidden on touch-only. Failed/stalled load falls back to placeholder (never a black frame); `video.loop=false` explicit.
- Idle watch (`idleWatch()` 1/min; test `test/idle.test.mjs`): idle PAUSED preview ends after `PREVIEW_IDLE_MS` 20 min (playing never cut); Settings panel closes after `SETTINGS_IDLE_MS` 15 min; wake lock re-requested on release and every 5 min.

Rule not loaded = never a club night. Overrides the Journey window's 19:00-19:15. Never cuts a lesson: while `journeyLessonRunning()` (slideshow, video `src`, caption prompt, loading overlay) the poll leaves `lastPhase` alone and waits; the scheduled show's finish goes to `lessonDoneView()` (card in Trek time, else check-in); 19:30 flips to check-in (cuts a lesson still running then). `setView('trek')` adopts `lastPhase='trek'` only when it IS the scheduled phase. ⇄ from card = check-in, from check-in in Trek time = card; Settings previews hide the card (`requestPlayback`, `startPreview`, `startTeachingSlides` hide `#trek-view`) and `endPreview()` hands back. Count chip: localStorage `awanaClubCounts.v1` `{v:1,at,byClub}` written by the embedded lobby (`lobby/src/lib/clubCountsStore.js`; numbers only; no second socket, never reach into the iframe) read by pure `trekCountFrom()` (same local day, <=12h, 0-999) on render, `storage` event and every poll; hidden when none. Title: pure `trekLessonTitleFor()`: tonight's uncancelled events titled `Trek: x` / `Trek - x` / `Trek · x` / `Trek Lesson N: x`, exactly one distinct title <=80 chars, else none (never guess). No countdown. Low = static (no keyframes); full = entrances in the motion block; view-flip stinger skips flips into the card. Configure mode: card hidden, nothing loaded.
- `lastPhase` tracks ONLY the scheduled phase. Manual toggle and video `ended` call `setView()` directly WITHOUT touching `lastPhase` (else next poll sees a fake flip and restarts lesson from 0). Re-verify when touching poller/handlers.
- `index.html` has two full-viewport layers toggled by `hidden` class, never destroyed (check-in iframe stays connected).
- Finishing video falls back to Check-in Display at once (after teaching slides if any; to the Trek card in Trek time), not at 19:15.
- Only the 18:30 scheduled show uses the splash; manual preview bypasses it.
