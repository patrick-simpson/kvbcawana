# CLAUDE.md — kvbc-awana (master rules for every app)

This one repo holds three apps for Kennebec Valley Baptist Church's Awana club:

- `lobby/`: signage and the projector screens (the sound room is KVBC Awana's display role, in `printer/`, since 2026-10-16).
- `worker/`: the sync Worker (Cloudflare), at the root since 2026-10-16; its rules stay in the lobby section below ("Settings panel, shared settings, sync service").
- `shared/`: the family's shared modules, data and brand kit (one master copy each), at the root since 2026-10-16; the site still serves it at `/lobby/shared/`. The lobby's lint and vitest cover it (`cd lobby && npm run lint`), and its rules stay in the lobby section below ("Brand kit"). Where the lobby section writes `shared/...` it means this folder.
- `journey/`: the Journey room kiosk.
- `classroom/`: the downstairs classroom screen (Cubbies, Sparks Large Group Time, the Sparks lobby), since 2026-10-17.
- `printer/`: KVBC Awana (the Windows app: print server, sound room display, or both), the public site, and the check-in page's source.

**Before changing anything inside an app folder, read that app's section in this file** (the `## App:` sections below). Each app's section is the authority for that app. The long-term plans are in `ROADMAP.md`.

## Git

- Push to `main` directly, as the owner's standing rule. Do not create branches or pull requests unless asked.
- Run the app's own checks before committing. Each app's section names them.
- Apps read each other's files. Before pushing, run every app's checks that CI would run for the files you changed: the "What changed" step in `.github/workflows/ci.yml` lists which paths start which jobs. For example, a change to `site/build.mjs` or `site/checkin/` also needs `cd printer && npm test`.
- Make one finding per commit.
- Model names are allowed in commit messages and files.
- Never work in the archived repos (`Print-TwoTimTwo-Labels`, `Awana-Check-in-Display`, `Journey-Display`). All work lands here.

## CI and deploy

- `.github/workflows/ci.yml` runs on every push and pull request, using Node 22. It runs each app's checks.
- `scripts/check-mirrors.mjs` confirms that shared files match across apps. The brand kit has one master copy, in `shared/brand/`. Copies are made at build time by `scripts/family-assets.mjs`. Do not edit the copies.
- Deploy runs only on `main`, after all checks pass. It builds the site and publishes it to Cloudflare Pages at awana.kvbchurch.org. It deploys the sync Worker only when the Worker's files changed.
- Every Worker deploy restarts the Durable Object and drops every screen's connection for a moment. That is accepted, so deploy the Worker whenever its changes need to go out.
- Journey kiosks reload only when Journey's own files change.
- The release workflow (`printer-release.yml`) builds the KVBC Awana installer (`desktop-release.yml` went with the old sound room app). Installer files are kept one day, then deleted by a cleanup job. The update feeds live on our site, not on GitHub's "Latest" releases.
- `brand-catalog-release.yml` is run by hand. It downloads the large catalog PDF to a release. Never add that PDF to the repo.
- Nightly bots commit to `main`. `lobby-update-calendar.yml` and `journey-update-lesson.yml` run each night. `clean-artifacts.yml` deletes old workflow files to save storage.
- `checkin-health.yml` (Wednesdays about 5:12 and 5:47 pm Eastern) and `handbook-print.yml` (4:00 pm Eastern daily, does its work only on club nights; "Handbook sheets" below) are scheduled checks/jobs; a failed run emails the owner.

## Costs: everything stays free

- Every part runs on a free plan: Cloudflare Workers free tier, Durable Objects and D1 free allowances, and GitHub Actions free minutes and storage.
- Any change that needs a paid plan is the wrong change.
- Encryption and decryption run in the browser or the app, never in the Worker. The Worker only routes and stores scrambled data.

## Keeping it simple and safe

- Prefer small, clear changes. Explain each change in plain English.
- Read a file before changing it.
- Use helper agents for simple, low-stakes jobs such as running a check or searching for text. Use Claude Haiku (the fast, low-cost model) for these. Keep harder work with the main model.
- Never store passwords, tokens, or passphrases in files.
- If a check fails, stop and report it. Do not change a test to make it pass.
