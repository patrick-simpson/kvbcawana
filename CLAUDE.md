## Git

## CI / deploy (`.github/workflows/ci.yml`, every push and PR; Node 22)
- Jobs: each app's checks as its old repo ran them; `scripts/check-mirrors.mjs` (contract and envelope vectors byte-identical across apps, printer's first; the brand kit has ONE committed copy (lobby `shared/brand/`), copied by `scripts/family-assets.mjs` into Journey `public/brand/` (plus Journey's shared modules) and the print server's `public/brand/` at build time; copies ignored; `printer/styles/family.css` is bundled by the site only, never copied; each app's `pretest`/`prebuild`/`prestart`, `site/build.mjs`, `release-app.yml` make them); `site` job builds the one site once per run (uploads `site/dist` + `site/lib/large-files.generated.js` as one-day `site-dist` artifact) and tests its Pages Function; lobby = parallel `lobby-checks` (lint, typecheck, vitest) + `lobby-e2e` (build, browser smoke; Chromium cached by `@playwright/test` version in `lobby/package-lock.json`); `setup-node` caches npm.
- "What changed" job skips lobby's 7.5-min suite and printer's one-minute one only when every changed file is one that suite never reads. Keep its lists in step when a suite starts reading another folder.
- Printer test scripts (`printer/scripts/test-*.cjs`, listed in `printer/scripts/run-tests.cjs`) run up to 4 at a time, each on its own port from `printer/scripts/free-port.cjs`; `npm test -- --serial` (or `TEST_SERIAL=1`) runs them one by one. A new suite takes its port from `free-port.cjs` and joins the runner's list.
- Deploy job (`main` only, after all green): takes the site the `site` job built (no rebuild; repo variable `SITE_ORIGIN` required, site job uses the same), installs only the Worker's packages (wrangler), deploys the sync Worker ONLY when its sources changed (every Worker deploy restarts the Durable Object and drops every screen's socket), publishes to Cloudflare Pages at awana.kvbchurch.org: `/` (printer's React site: public page; lobby `#lobby`, projector `#projector`, Journey `#journey`; old `/lobby/about.html`, `/journey/about.html` 301 there), `/lobby`, `/lobby/countdown` (projector), `/journey`, `/checkin` (the ONE check-in page, phones and the desk, on the Worker's desk routes; `/desk` 301s there; `/checkin/classic` = the old relayed page until 2026-10-14), `/settings` (`ROADMAP.md#settings-page`), `/api` (Worker), `/updates` (update feeds). Journey stamped with a hash of its own files: only a Journey change reloads kiosks.
- Releases: `printer-release.yml`, `desktop-release.yml` (dispatch with version, `ref: main`; thin callers of reusable `release-app.yml`): run tests, create tag (`printer-v*`/`desktop-v*`), build + smoke-test on Windows, publish `make_latest: false`, commit the app's update feed into `site/updates/` (only moves forward). `delete-release.yml` (pick app) undoes a bad release. Update feeds are OURS not GitHub "Latest": electron-updater generic provider at `awana.kvbchurch.org/updates/printer/` and `/updates/lobby/` (channel lobby), absolute URLs to this repo's release assets (Pages can't host the 170 MB installers). Release workflows keep installer artifacts 1 day (`retention-days: 1`).
- `brand-catalog-release.yml` (by hand): downloads the Awana Clubs 2026-27 catalog PDF (~50 MB, brand kit source) and uploads it to release `brand-catalog-2026-27`; NEVER in the tree.
- Bots (commit to `main` with rebase-and-retry, dispatch `ci.yml`): `lobby-update-calendar.yml`, `journey-update-lesson.yml` nightly. `clean-artifacts.yml` weekly/by hand deletes workflow artifacts older than a day (0.5 GB Actions storage). Per-app `.github/` folders are gone; the one manual workflow that still matters is `lobby-update-snapshots.yml` (regenerates lobby visual baselines; dispatch by hand).
